Local GPU SSH + SkyPilot (Docker Desktop / k3s)
================================================

Objetivo
--------
Tener una prueba reproducible donde un job de SkyPilot en `ssh/local-gpu` confirme:
1) `nvidia-smi` funcional dentro del job.
2) PyTorch con CUDA disponible.
3) Un mini workload GPU (matmul) exitoso.

Estado validado (2026-04-22)
----------------------------
Marcadores observados en logs del smoke:
- `SMOKE_START`
- `GPU_OK`
- `TORCH_CUDA_OK: NVIDIA GeForce RTX 4070 Laptop GPU`
- `TORCH_GPU_MATMUL_OK: ...`
- `SMOKE_PASS`

Ejecucion automatizable (recomendada)
-------------------------------------
Desde la raiz del repo:

```bash
bash k3s/sky/e2e-local-gpu-smoke.sh
```

Opcional (mas rapido para debug):

```bash
SKY_SSH_UP_TIMEOUT=60 JOB_TIMEOUT_SECONDS=1200 bash k3s/sky/e2e-local-gpu-smoke.sh
```

Que hace este script
--------------------
1. Reinicia `sky-local-gpu` con GPU y flags de sistema.
2. Garantiza `/usr/lib/wsl/lib/libdxcore.so` dentro del nodo local.
3. Verifica GPU del nodo (`docker exec sky-local-gpu nvidia-smi`).
4. Ajusta `/root/.sky/config.yaml` (runtimeClass `nvidia` para `ssh/local-gpu`).
5. Ejecuta `sky ssh up` con timeout (no se queda colgado indefinidamente).
6. Cancela requests colgados `sky.ssh_node_pools.up` si quedaron en RUNNING.
7. Pre-pull de imagen en k3s containerd:
   `k3s crictl pull docker.io/takenking9879/ray-train-ssh:2.53.0`
8. Lanza smoke `k3s/sky/ray-gpu-smoke-local.yaml`, espera estado final y valida markers.
9. Limpia cluster `local-smoke` (si `CLEANUP_CLUSTER=1`, default).

Smoke YAML usado
----------------
Archivo: `k3s/sky/ray-gpu-smoke-local.yaml`

Puntos clave del run:
- ejecuta `nvidia-smi`
- hace `unset CUDA_VISIBLE_DEVICES` antes de PyTorch
- valida `torch.cuda.is_available()`
- corre matmul pequeño en GPU

Nota importante de Ray/SkyPilot
-------------------------------
En este flujo local, Ray puede dejar `CUDA_VISIBLE_DEVICES=""` para jobs CPU.
Si no se limpia esa variable, PyTorch puede reportar `cuda=False` aunque `nvidia-smi` vea GPU.
Por eso el smoke incluye:

```bash
unset CUDA_VISIBLE_DEVICES
```

Validacion manual minima (si quieres correrlo por partes)
---------------------------------------------------------
1) Nodo local:

```bash
bash k3s/sky/start-local-gpu-node.sh
docker exec sky-local-gpu nvidia-smi
```

2) Subir runtime SSH (timeboxed):

```bash
bash k3s/sky/sky-ssh-up-timeboxed.sh 60
```

3) Cancelar request colgado (si aplica):

```bash
API_CTN=$(docker ps --format '{{.Names}}' | rg '^k8s_skypilot-api_' -m1)
docker exec "$API_CTN" sky api status
docker exec "$API_CTN" sky api cancel <request_id_de_sky.ssh_node_pools.up>
```

4) Pre-pull imagen en k3s:

```bash
docker exec sky-local-gpu bash -lc 'k3s crictl pull docker.io/takenking9879/ray-train-ssh:2.53.0'
```

5) Lanzar smoke:

```bash
API_CTN=$(docker ps --format '{{.Names}}' | rg '^k8s_skypilot-api_' -m1)
cat k3s/sky/ray-gpu-smoke-local.yaml | kubectl exec -i -n skypilot my-skypilot-api-server-56dd5f5bf7-n7jl4 -- sh -lc 'cat > /tmp/ray-gpu-smoke-local.yaml'
docker exec "$API_CTN" sky launch -y --cluster local-smoke /tmp/ray-gpu-smoke-local.yaml
docker exec "$API_CTN" sky logs local-smoke --no-follow --tail 220
```

6) Cleanup:

```bash
docker exec "$API_CTN" sky down local-smoke -y
```

Troubleshooting rapido
----------------------
- `sky ssh up` se queda despues de `runtime is up`:
  - comportamiento conocido en este entorno; usar helper timeboxed.
- Cluster en `INIT` por mucho tiempo:
  - revisar pulls de imagen en pod events.
  - hacer pre-pull con `k3s crictl pull ...`.
- `nvidia-smi` OK pero `torch.cuda.is_available()==False`:
  - verificar que el run haga `unset CUDA_VISIBLE_DEVICES`.
