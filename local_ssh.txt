Local GPU SSH Node Pool — End-to-End Test Sequence
====================================================

PREREQUISITES
-------------
- WSL with Docker + nvidia-container-toolkit installed
- ~/.sky/ssh_keys/local-gpu key pair exists (create if not: ssh-keygen -t ed25519 -f ~/.sky/ssh_keys/local-gpu -N "")
- KUBECONFIG points to k3s cluster
- helm + kubectl available


STEP 1 — Build and push Docker image
--------------------------------------
docker build -f k3s/sky/Dockerfile.local-gpu \
  -t takenking9879/ray-train-ssh:2.53.0 .

docker push takenking9879/ray-train-ssh:2.53.0

# Verify image exists:
docker images | grep ray-train-ssh


STEP 2 — Start local GPU container on WSL host
------------------------------------------------
bash k3s/sky/start-local-gpu-node.sh

# Verify container running with GPU access:
docker exec sky-local-gpu nvidia-smi
# Expected: GPU table with your card listed

# Verify SSH port is open:
ss -tlnp | grep 2222
# Expected: LISTEN on 0.0.0.0:2222


STEP 3 — Test SSH from WSL host to container
----------------------------------------------
ssh -p 2222 \
  -i ~/.sky/ssh_keys/local-gpu \
  -o StrictHostKeyChecking=no \
  root@127.0.0.1 \
  "echo SSH_OK && nvidia-smi | head -3"
# Expected: SSH_OK + GPU line


STEP 4 — Deploy Helm with SSH node pool config
------------------------------------------------
helm upgrade --install skypilot ./k3s/sky/helm/skypilot \
  --namespace skypilot \
  --set-file apiService.sshNodePools=k3s/sky/ssh_node_pools.yaml \
  -f k3s/sky/helm/values.yaml

# Verify config landed in pod:
kubectl exec -n skypilot deployment/skypilot-api-server -- \
  cat ~/.sky/ssh_node_pools.yaml
# Expected: local-gpu: user: root, port: 2222, hosts: [host.docker.internal]


STEP 5 — Copy SSH private key into API server pod
--------------------------------------------------
# One-time; survives pod restarts only if key is baked into image or re-copied after restarts.
# For persistence consider a K8s secret instead.

POD=$(kubectl get pod -n skypilot -l app=skypilot-api-server \
  -o jsonpath='{.items[0].metadata.name}')

kubectl exec -n skypilot $POD -- mkdir -p /root/.sky/ssh_keys

kubectl cp ~/.sky/ssh_keys/local-gpu \
  skypilot/$POD:/root/.sky/ssh_keys/local-gpu

kubectl exec -n skypilot $POD -- \
  chmod 600 /root/.sky/ssh_keys/local-gpu

# Verify key present:
kubectl exec -n skypilot deployment/skypilot-api-server -- \
  ls -la /root/.sky/ssh_keys/local-gpu


STEP 6 — sky check ssh
------------------------
kubectl exec -n skypilot deployment/skypilot-api-server -- sky check ssh
# Expected: local-gpu   ✓   1 node(s)

# If FAILED: pod cannot reach host.docker.internal:2222
#   - Check container is running: docker ps | grep sky-local-gpu
#   - Check host.docker.internal resolves from pod:
#     kubectl exec -n skypilot $POD -- getent hosts host.docker.internal
#   - Check pod can TCP-reach port 2222:
#     kubectl exec -n skypilot $POD -- nc -zv host.docker.internal 2222


STEP 7 — Smoke YAML (minimal GPU verify, no pip install)
---------------------------------------------------------
kubectl exec -n skypilot deployment/skypilot-api-server -- \
  sky launch -y --cluster-name local-smoke \
  /path/to/k3s/sky/ray-gpu-smoke-local.yaml

# Stream logs:
kubectl exec -n skypilot deployment/skypilot-api-server -- \
  sky logs local-smoke
# Expected lines: SMOKE_START / GPU_OK / TORCH_CUDA_OK: <GPU name> / SMOKE_PASS

# Cleanup:
kubectl exec -n skypilot deployment/skypilot-api-server -- \
  sky down local-smoke -y


STEP 8 — Full training YAML via Airflow UI (end-to-end)
---------------------------------------------------------
1. Open Airflow UI -> training_dag_skypilot
2. Trigger with dag_conf JSON:
   {
     "model_type": "pytorch",
     "gpu_resource_constraints": {
       "providers": ["local"]
     },
     ... (other required training params)
   }

3. Verify in task logs:
   - Task "build_sky_job": YAML = ray-gpu-training-local.yaml, any_of = []
   - Task "launch_sky_job": sky launch uses infra: ssh/local-gpu (no cloud VM provisioned)
   - METRICS_SOURCE = local_docker, GPU_PRICE_PER_HOUR = 0, USE_SPOT = false

4. Check sky logs from Airflow task output or:
   kubectl exec -n skypilot deployment/skypilot-api-server -- \
     sky logs <job-name>
   # Expected: setup (~30s, --system-site-packages), run section completes


TROUBLESHOOTING
---------------
Container not reachable from pod:
  → host.docker.internal only resolves in Docker Desktop K8s.
  → In k3s on WSL, may need to use host IP instead.
  → Get host IP: ip route | awk '/default/ {print $3}'
  → Update k3s/sky/ssh_node_pools.yaml hosts: [<that IP>] and redeploy.

sky check ssh shows 0 nodes:
  → Check SSH key perms in pod (must be 600).
  → Check authorized_keys in container has the PUBLIC key:
    docker exec sky-local-gpu cat /root/.ssh/authorized_keys

Training job fails at setup:
  → Check Ray version in container matches ray in training YAML run: section.
  → Check CUDA visible: docker exec sky-local-gpu python3 -c "import torch; print(torch.cuda.is_available())"
